# Contributing Guidelines

Thanks for taking the time to contribute! Please review these guidelines before submitting a pull request.

## Quick Rules

- One entry per pull request where possible — makes review and history easier.
- Search the list first to avoid duplicates.
- Entries must be actively maintained, publicly accessible, and genuinely relevant to lead generation (prospecting, outreach, capture, qualification, conversion, or the strategy/learning resources around them).
- No affiliate links, referral links, or tracking parameters in URLs.
- Alphabetical order is not required within categories — new entries can go wherever fits contextually, but don't reorder unrelated entries in your PR.

## Entry Format

Follow the existing style exactly:

```markdown
- [Name](https://example.com/) - Short, neutral, factual description, ending in a period.
```

- Description should be one line, ideally under ~120 characters.
- Describe what the tool/resource *does*, not why it's the best — avoid superlatives like "amazing," "best-in-class," or "revolutionary."
- No emojis in entries.
- Use sentence case for the description (capitalize only the first word and proper nouns).

## Adding a New Category

If your entry doesn't fit an existing category:

1. Only propose a new category if you have 3+ entries that belong in it, or open an issue first to discuss.
2. Add the new heading in the same style as existing ones (`## Category Name`).
3. Add a corresponding link in the [Contents](README.md#contents) table of contents.
4. Keep category names concise (2-4 words).

## What Won't Be Accepted

- Dead links or discontinued products.
- Entries with no clear relevance to lead generation.
- Self-promotional entries with inflated or unverifiable claims.
- Paywalled resources presented without noting they're paid (mention "(paid)" if the core offering isn't free).
- Duplicate tools already covered by an existing, more established entry — unless yours offers meaningfully different functionality.

## Submitting a Pull Request

1. Fork the repository.
2. Create a branch: `git checkout -b add-tool-name`.
3. Make your change, following the format above.
4. Run through the checklist below before opening the PR.
5. Open a PR with a short description of what you added and why it belongs.

### Checklist

- [ ] Entry follows the `[Name](link) - Description.` format
- [ ] Link goes directly to the resource (no redirects/trackers)
- [ ] Description is factual, one line, no marketing language
- [ ] Placed under the correct category
- [ ] No duplicate of an existing entry
- [ ] Spell-checked

## Code of Conduct

Be respectful and constructive in discussions and reviews. Disagreements about inclusion are fine — keep them focused on relevance and quality, not personal.

## Questions

If you're unsure whether something belongs, open an issue first rather than a PR — happy to discuss before you do the work.
